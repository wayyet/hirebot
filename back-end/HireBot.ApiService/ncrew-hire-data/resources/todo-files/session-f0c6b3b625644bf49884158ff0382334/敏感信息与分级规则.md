# 敏感信息与分级规则

## 1. 分级目标

对企业数据资产中的敏感信息进行统一识别、分级和处理，避免敏感数据在展示、导出、共享、模型调用或日志记录中被不当使用。

## 2. 敏感级别定义

| 级别 | 名称      | 定义                    | 示例                      | 处理要求           |
| -- | ------- | --------------------- | ----------------------- | -------------- |
| L1 | 公开/低敏信息 | 不涉及个人隐私或商业敏感，可在内部正常使用 | 客户行业、城市、公开企业名称          | 正常使用           |
| L2 | 内部敏感信息  | 泄露后可能造成业务影响           | 联系人姓名、邮箱、部门、订单金额        | 权限控制、展示脱敏      |
| L3 | 高敏感信息   | 泄露后可能影响个人权益或企业安全      | 手机号、详细地址、合同金额、客户名单      | 加密存储、导出审批、访问留痕 |
| L4 | 核心敏感信息  | 泄露后可能造成重大合规或安全风险      | 身份证号、银行卡号、密码、密钥、健康/金融信息 | 默认阻断、强脱敏、严格审批  |

## 3. 常见敏感信息类型

| 类型     | 示例字段                | 建议级别  |
| ------ | ------------------- | ----- |
| 个人身份信息 | 姓名、身份证号、护照号         | L2-L4 |
| 联系方式   | 手机号、邮箱、地址           | L2-L3 |
| 账户凭证   | 密码、Token、API Key、密钥 | L4    |
| 财务信息   | 银行卡号、交易金额、发票信息      | L3-L4 |
| 企业经营信息 | 客户名单、合同金额、报价、销售策略   | L2-L3 |
| 行为日志   | 登录IP、设备ID、访问轨迹      | L2-L3 |
| 特殊敏感信息 | 医疗、金融、法律、未成年人相关信息   | L4    |

## 4. 分级判断规则

| 判断维度       | 判断方式                    |
| ---------- | ----------------------- |
| 是否可识别个人    | 能直接或间接识别个人，则至少为L2       |
| 是否涉及财务/交易  | 涉及金额、账户、支付信息，通常为L3及以上   |
| 是否涉及认证凭证   | 密码、密钥、Token一律L4         |
| 是否涉及客户商业机密 | 客户名单、合同、报价、项目计划通常为L2-L3 |
| 是否属于监管敏感领域 | 医疗、金融、法律等信息按高敏处理        |

## 5. 使用规则

* L1：可在授权业务场景中正常使用。
* L2：需控制访问范围，展示时建议部分脱敏。
* L3：导出、共享、模型调用前需审批和留痕。
* L4：默认禁止明文展示、导出和外发，必要时走专项审批。
