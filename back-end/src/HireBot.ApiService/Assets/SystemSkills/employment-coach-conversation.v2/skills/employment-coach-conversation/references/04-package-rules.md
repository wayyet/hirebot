# 模板包文件修改规则

本文档定义雇佣教练**何时以及如何**修改工作模板包中的 `SOUL.md` / `IDENTITY.md` / `AGENTS.md` 三个配置文件。

> 名词速查: 不熟悉的术语见 [01-glossary.md](01-glossary.md)

---

## 1. 修改权限

| 文件 | 路径 | 权限 | 写入语义 |
|---|---|---|---|
| SOUL.md | `config/SOUL.md` | ✅ 可写 | 角色身份与核心使命（"它是谁、为什么存在"） |
| IDENTITY.md | `config/IDENTITY.md` | ✅ 可写 | 身份声明与对外展示（名字、形象、口吻） |
| AGENTS.md | `config/AGENTS.md` | ✅ 可写 | 行为规范与边界约束（能做什么、不能做什么） |
| MEMORY.md | `config/MEMORY.md` | ❌ **只读** | 模板预设记忆，永远不动 |

---

## 2. 监听触发条件

雇佣教练持续监听对话，**同时**满足以下两类信号才触发治理流程：

**信号1——身份描述类关键词**:
名字、性别、形象、口吻、语气、使命、定位、责任、规则、约束、不能、必须、底线

**信号2——修改类动词**:
改、换、不是、应该叫、调整、补充、加上、去掉、不要

不满足两类同时出现 → 按普通对话处理。

---

## 3. 混合反问机制

### 高置信度（用户表达明确、识别到的内容唯一）
→ 直接更新文件 + 一行轻量反馈：

- "好的，名字已经改成『小琪』。"
- "记下了，AGENTS.md 里加上『不主动承诺金额』。"

### 低置信度（目标值模糊、可能误读）
→ 短反问，回放识别到的具体内容：

- ✅ "你是想把它的名字从『小智』改成『小琪』，对吗？"
- ❌ "你是要修改身份信息吗？"（太泛，禁止这样问）

### 用户回应处理
- 肯定（对、是的、嗯、没错）→ 更新文件
- 否定（不是、不对、我是说……）→ 不更新，按用户新表述重新识别
- 答非所问/转移话题 → 视为不确认，不更新，不追问

### 连续修改
用户在反问待确认状态下又抛出新修改意图 → 取消上一次反问，用新意图重新发起。**永远只有一个反问待确认**。

---

## 4. 改动反向触发 TODO 复核

### 触发判定

只在改动属于**判定/边界/数据访问范围**层面时提醒。改名字、改口吻不触发。

| 改动类型 | 可能影响的 TODO |
|---|---|
| SOUL.md 使命范围调整 | 全部 skill TODO 的存在合理性 |
| IDENTITY.md 名字/口吻调整 | 通常不影响（不触发） |
| AGENTS.md 判定规则/阈值/必转条件改动 | 含相同维度判定的 skill TODO |
| AGENTS.md 红线/"不能做的事"改动 | 含越线动作的 skill 和 external TODO |
| AGENTS.md 数据/隐私/凭据范围改动 | 全部 external TODO 的 access scope |

### 处理流程

1. 发现影响 → 在修改确认后追加一句简短提醒：
   > "好，AGENTS.md 已经改了。顺便——你刚才改的这条可能影响『退货资格预判』，要不要回头过一下？"

2. 用户回应：
   - **要/嗯好** → 相关 `done` TODO 用 `todo.update` 切回 `open`（或新建关联 TODO），逐条复核
   - **不要/先不管** → 不动状态
   - **答非所问** → 默认不动，不再追问

### 约束
- 一次改动最多列 2-3 条最直接相关的 TODO。
- 复核过程中每条 TODO 一个回合，不批量抛给用户。

---

## 5. 安全红线

- **永远不修改 MEMORY.md**。用户问"怎么记住事情" → 告知模板预设，部署后再观察。
- **不暴露内部路径**。不说沙箱绝对路径、orchestrator、hooks 等概念。
- **凭据值绝不写入配置文件**。凭据入凭据表单，走系统层加密存储。
